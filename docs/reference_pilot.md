# Reference-guided GenAI pilot

[Open in Colab](https://colab.research.google.com/github/MBG0903/GNR_Design_Project/blob/main/notebooks/Reference_Guided_Pilot.ipynb).

The first experiment compares the current full-image generation prompt with the same prompt plus two similar approved sketch/output pairs. It is retrieval-guided generation, not fine-tuning. Local pretrained CLIP selects examples by sketch similarity; it never generates or corrects textile pixels. Sunburst is requested through the existing OpenAI image-edit API configuration, subject to the user's account access.

## Run

1. Open the notebook and enable the existing `OPENAI_API_KEY` Colab Secret.
2. Run the cells in order (or Run all for the provisional pilot). Mount Drive when Colab asks. The default input folders are `MyDrive/GNR Design Data-Set/Stage_2` and `Stage_3`. Change `DATA_ROOT` if necessary. No images are embedded in cells.
3. The audit validates paired names, dimensions and exact designer colours. Problems are recorded in `audit/audit.json`; invalid ground truth is not silently changed.
4. A `groups.csv` is suggested beside the dataset if absent. Every crop/variant must share the original design's `design_id`. Confirm group IDs and alignment before setting `GROUPS_REVIEWED=True`; inferred filenames cannot establish independent designs. With False, results are explicitly provisional. Existing CSVs are preserved, and missing mappings stop the audit.
5. Sketch indexing runs locally in Colab, caching vectors on Drive. A GPU speeds it up; CPU works. The first run downloads pretrained CLIP weights from Hugging Face. Inspect the selected-example preview to assess whether this generic embedding retrieves useful textile motifs.
6. The default pilot makes up to **10 paid image calls**: five validation designs, rules-only and similar-example methods. Both use the same model, prompt, quality and native restoration. There is one output per method, with no cherry-picking.
7. Review native PNG/BMP images, raw outputs, prompts, difference maps, `scores.csv`, `summary.json` and `pilot_review.zip`. They remain under `MyDrive/GNR Textile Runs/Reference_Pilot_v1/results`. Fill the separate `designer_review.csv` with semantic-rule findings and editing effort.

The image API key and Drive files are available in the user's Colab session, not this cloud workspace. Preparing this notebook does not run generation on the 1,700+ pairs. No real retrieval-pilot accuracy has been measured yet.

## Evaluation contract

- Approximately 80/10/10 of families are reference/validation/test. Exact duplicate sketches or targets and declared family IDs are merged transitively. Pair proportions can differ from family proportions. Inferred family IDs must be checked for renamed crops/variants.
- The final test split is not indexed, retrieved or generated by this notebook. The five-design pilot uses validation families. Fix the method after validation before using the test set in a later experiment.
- Only sketch embeddings rank references. Each query receives examples from distinct reference families. Query designer targets are held out from generation; all selected files are rechecked before paid requests.
- Similarity is measured at original coordinates with no comparison-time alignment, resizing or target palette conversion. Pair registration must be confirmed by the designer. Generation can still shift motifs even though its final dimensions match the sketch.
- Report pixel agreement, red IoU and red Dice per image and as equal-design means. Compare methods on designs completed by both methods. The summary also counts example-guided designs reaching 70%/80% **red IoU**; that explicit metric is stricter than generic pixel agreement and is not a rule pass rate.
- A five-design, one-sample-per-method run is an exploratory signal. Model randomness and reference relevance can affect results. Expand the validation sample and repeat fixed trials before making broad accuracy claims.
- Size and exact red/white palette are deterministic. The prompt requests density, semantic two-pixel gaps, intentional white channels, shorter front anchors and 3→2→1 or 2→1 staircases with increasing counts. These remain unverified until inspected. No target copying, rejected strip fitting or blanket morphological repairs are applied.

## Resume and costs

Reuse the same experiment folder to reuse cached embeddings and completed drafts. Changed configuration or input pixels are rejected; choose a new experiment name instead of mixing results. Started requests are marked before API submission. Interrupted requests block automatic repetition because the provider may already have billed them. Inspect API usage and the incomplete method folder before deleting just that method folder to explicitly retry. SDK automatic retries are disabled. API failures retain completed outputs and record only error type/status, not potentially sensitive exception text.

No model weights are trained. A useful retrieval result would justify expanding the pilot; an insufficient result would guide selection of a generative model with verified paired-image training support. The existing editing panel can continue collecting designer corrections independently.

## Validation performed here

Automated tests cover both naming patterns, crop-family grouping, split leakage rejection, embedding cache integrity, reference-only API payloads, native PNG/BMP outputs, independent metric calculation, resume without extra requests, interrupted-request handling, and notebook compilation/runtime consistency. Embeddings and image API responses are mocked in these tests. They validate orchestration, not CLIP relevance, Sunburst quality, or live Colab installation.
